# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Continuous Audio Overlay is a small always-on-top Windows Forms overlay (single project, no tests) for controlling the host machine's audio: system volume, default output device, Windows media session transport (play/pause/next/prev for Spotify, YouTube, etc.), and built-in internet radio playback via BASS. It is aimed at people who work in remote desktop sessions and don't want to minimize them to change audio settings.

## Build & run

```
dotnet build ContinuousAudioOverlay.sln
dotnet run --project ContinuousAudioOverlay.csproj
```

- Target is `net10.0-windows10.0.22621.0`, x64 only (`PlatformTarget` is x64 because the native `bass.dll` in the repo root is x64). The Windows SDK TFM is what makes `Windows.Media.Control` (WinRT media sessions) available.
- There is no test project and no linter configured.
- The `NU1701` warnings about AudioSwitcher being restored for .NET Framework are expected and harmless.
- The `Bass.Net` reference's `HintPath` points outside the repo (`..\..\..\Desktop\Bass24.Net\...`). The build still resolves it from `Libraries\Bass.Net.dll`, because that file is a `Content` item. Don't remove that item.

## Architecture

- **`Form1`**: the whole overlay UI and most of the logic. It owns:
  - **Output devices / volume**: `AudioSwitcher.AudioApi.CoreAudio` (`CoreAudioController`). Device changes made outside the app are observed via `AudioDeviceChanged`. The `_isOutputDeviceChangingFromSystem` / `_isOutputDeviceChangingFromApplication` flags keep the dropdown handler and the system-change subscription from triggering each other in a loop. When the device changes while the radio is playing, the radio stream is restarted (`ChangeRadioIndex`) so BASS picks up the new default device.
  - **Media session info**: `GlobalSystemMediaTransportControlsSessionManager` supplies the title/artist/thumbnail of the current session. `Helpers/ProcessNameHelper` maps a session's `SourceAppUserModelId` to a readable app name through `SHGetPropertyStoreForWindow`, with fallbacks.
  - **Media transport commands**: these are not sent through the WinRT session API. `Send(AppCommands)` posts `WM_APPCOMMAND` to a hidden form running its own STA message-loop thread. Mute works the same way.
  - **Radio vs. media exclusivity**: starting the radio pauses any playing media session, and pressing a media transport button stops the radio. `_resumeRadioIndex` / `_previousRadioIndex` back the "resume" and "previous station" behaviour. The last dropdown entry is always the `<no radio>` sentinel.
  - **Borderless window**: `WndProc` turns client-area hits into `HTCAPTION` so the window can be dragged anywhere. "Fold" shrinks the form to 40×30. The unfolded size is hard-coded to 260×409 in `FoldPictureBox_Click`.
- **`BassService`**: radio playback and the radio list.
  - Loads `Libraries\Bass.Net.dll` at runtime with `Assembly.LoadFrom`. Most BASS calls go through reflection (`_bassType.GetMethod(...)`), while a few (`BASS_ChannelSetSync`, `BASS_ChannelGetTags`) use the compile-time `Un4seen.Bass` reference directly.
  - `PlayRadio` cancels any in-flight start through `_playRadioCts`. `ReleaseBassResources` fully frees BASS (`BASS_Free`) on every station change, and the next play calls `BASS_Init` again.
  - Stream metadata (`StreamTitle='Artist - Title'`) arrives through a `BASS_SYNC_META` callback and is raised as `OnMetaDataChanged`. That callback runs on a BASS thread, so UI updates marshal back with `Invoke`.
  - **Radio list**: stored at `%LOCALAPPDATA%\ContinuousAudioOverlay\RadioList.xml`, with root `<Radios>` and `<Radio><RadioName/><RadioURL/></Radio>` entries. It is created with two default stations if missing. The README's `Resources\RadioList.xml` location is outdated.
- **`SettingsForm`**: add/edit/remove stations. It creates its own `BassService` only to read and write the XML. `Form1` reloads the radio list when the settings form closes.
- **`FlatComboBox`, `TrackBarCustom`**: owner-drawn controls that give the flat amber (`255,191,0`) / yellow-hover look used throughout.

## Conventions

- Code files are organized into `#region` blocks (Fields, Constructor, Win32 Interop, Private methods, Event handlers, Overrides). Put new members in the matching region.
- Some older comments are in Czech. Leave them as they are unless you're editing that code.
- `*.Designer.cs` and `.resx` files are generated by the WinForms designer. Keep hand edits to them minimal and consistent with designer output.
